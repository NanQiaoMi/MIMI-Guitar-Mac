# 原网页界面还原与卡顿修复计划

日期：2026-10-25。范围：接续 0.2.2，不重新设计产品。

## 目标与基准

- 以交付包 `src/pages`、`src/components`、`src/styles` 为界面基准，恢复页面顺序、内容层级、控件位置、文案、尺寸、字体与颜色。
- 保留原网页全部功能，以及已经实现的本地导入、离线资源、macOS 文件面板、菜单和快捷键。原生附加入口应放在对应功能的菜单或面板中。
- 性能修改保留可见功能与动效；先处理重复计算、磁盘工作和状态更新，再以实际数据决定下一步。
- 当前分支 `feature/macos-native`，以未提交改动交付。原有用户修改、个人数据、0.2.1/0.2.2 产物保留。

## 已确认差异与工作顺序

| 阶段 | 原网页基准 | 原生版已确认差异 | 修正要求 |
| --- | --- | --- | --- |

| 2 找谱 | `TabCardGrid.svelte` 两行过滤区和三种视图 | 难度、谱型等改成菜单，结构与网页不同 | 恢复分类、搜索、视图切换、难度/谱型按钮及其余筛选；保留分页和试听 |
| 3 我的谱 | `PersonalLibrary.svelte` 纵向搜索添加、导入、待练、已归档、收藏、个人导入、工坊工程 | 改成五个标签页 | 恢复纵向内容分区，保留备注、排序、归档、导入和工程操作 |
| 4 创作 | `ScoreStudioApp.svelte` 纵向 header/toolbar、整宽画布、底部工作台/调音台；歌词/帮助/草稿弹层 | 左右常驻 226/300 栏压缩谱面 | 恢复整宽画布、底部 dock 与原入口；已有功能迁入对应弹层，不删除 |
| 5 播放与详情 | `ScorePlayer.svelte` 紧凑 pill 工具区、轻量进度行、按需面板；详情信息在播放器前 | 工具区拆成固定多行；详情置于固定高度区 | 恢复网页层级、控件与展开位置；保留播放、导入和音源修复 |
| 6 其余页面 | practice/data/article/account 等对应原组件 | 逐页核对中 | 按已证实差异修改，未完成的逐项列出，不用占位代替 |
| 7 性能 | 保留同等内容与交互 | Studio 每次编辑全工程 JSON 往返、同步草稿写入/目录扫描、逐版本串行保存 | 后台原子草稿写入、合并重复持久化、避免重复扫描；保存/切换/离开须可靠完成，保留冲突保护 |

首页现有区块顺序与原网页基本对应。还原工作应以实际差异为依据，不另加设计方向。

## 分工与依赖

- 主代理：确定原网页基准、安排文件所有权、核对修改、组织构建/截图/运行诊断与交付。
- GPT-6 Luna Max 实现代理 A：全局导航、首页、曲库、个人资料等 Views 文件。
- GPT-6 Luna Max 实现代理 B：播放器、曲谱详情、创作界面；先补充诊断截图工具。
- GPT-6 Luna Max 实现代理 C：Studio 数据与保存链性能；与界面文件分离。
- 先冻结原生源码供基线构建，再并行实现；构建和性能测量按顺序运行，避免资源争用。

## 检查与完成条件

1. 编译真实产品源码；修复编译错误。此工作不新增或运行单元测试套件。
2. 在隔离的临时个人资料目录中抓取本进程窗口的修改前/后界面；不读取、清空或迁移用户个人库。记录尺寸、路由与资源版本。
3. 检查导航、曲库过滤/三种视图、个人资料各分区、播放器和创作页的结构及全部操作入口。
4. 使用已有诊断检查真实曲谱加载/连续播放、导入、Studio 编辑/撤销/重做/保存/试听。数字音频检查与扬声器实际听感分别报告。
5. 同一设备、同一诊断驱动、相同资源与编译选项下比较修改前/后性能。主队列延迟不称作帧率。诊断中 Core/App 都用 `-Osize`；当前发布脚本实际是 Core `-O`、App `-Osize`，并且没有诊断宏，发布包仍须单独核验。
6. 如生成新版，使用独立 0.2.3 输出目录，检查 Universal 2、资源完整性、签名和安装包；保留既有版本与用户正在使用的应用。

## 证据边界

- 当前原网页 `127.0.0.1:4336` 不可连接，项目 `node_modules` 为空，Docker daemon 暂不可连接。不会自动恢复数据库或升级依赖；同状态网页截图尚未取得。
- 以上结构差异由原始源码与原生源码直接对照确认；具体像素一致性与全部动态状态尚未验收。
- 基线源码：`.build/runtime-audit-023/baseline-native/Sources`；摘要：`baseline-source-hashes.json`。本轮结果另行记录，旧版诊断不充当本轮通过证据。

## 本轮基线发现

- 冻结源码构建的诊断窗口已抓取六个页面。来源/摘要/限制见 `.build/runtime-audit-023/baseline-visual-evidence.json`。这是本进程视图快照，不是已安装应用的系统截屏。
- 实际主窗口详情/练习嵌入路径没有取得可见谱面；固定高度详情区与播放器剩余高度布局需要修复。不能由独立 Player 根视图通过推断主窗口路径通过。
- 空个人资料首次进入 Studio 时，旧代码只在 `project != nil` 时挂载 WKWebView，而新建又要求 WK 引擎已 boot，导致首次入口相互等待。需要常驻同一个引擎视图，并协调初始资料加载与 boot，防止默认空白工程抢占显式导入/打开请求。
- 六张基线 PNG 已生成；末尾 JSON 因可选字符串被映射成 Character 数组而序列化失败。此工具错误保留并修复，不计作六页功能检查通过。
- 本轮旧版 Home/Catalog 各三轮运行完成。Studio 实际录入三轮有一轮第二次编辑后等待 AlphaTab 重绘超时，原因尚未归因；记录保留，失败运行不纳入完整 12 秒性能比较。
- 独立只读审查发现旧草稿文件名清洗可碰撞。新的后台管线需使用原始 ID 摘要命名并保留旧文件兼容读取，回读核对 ID，防止装入或删除另一工程的草稿。

## 本轮实现及早期检查记录（最终结果见下节）

- 已恢复个人资料的七个纵向分区、曲库分组筛选、主导航与全宽页脚，以及创作页的整宽谱面和底部工作台/调音台。草稿、歌词和高级属性放回对应弹层，原有操作入口保留。
- 详情页按原站顺序排列标题/标签/操作/说明、播放器及后续元资料。播放器工具栏可换行；谱面获得明确视口，避免滚动容器只留下空卡片。空个人库首次进入创作页时引擎常驻，仅在初始资料读取成功后创建默认工程。
- 编写过程的只读复核补回了“定位当前拍”，修正毫秒时钟、停止时的实际播放位置，以及稳定视图区的播放/脏状态/引擎就绪缓存键。
- 草稿编码、目录读取与原子写入改到串行后台队列；重复自动保存按 450 ms 空闲、最长 1.8 s 合并，保留手动保存与版本冲突检查。工程草稿使用原始 ID 的 SHA-256 文件名；兼容旧文件前先核对其中的 ID。
- 手动保存、导出与切换工程先等待已接受的编辑；离开时对编辑排空和最新确认草稿写入设置总时限，旧 WebView 的销毁也有时限。引擎没有回传的编辑、磁盘失败和强制结束不被描述为“已保存”。
- `integrated-stage7` 的正常 App 与诊断目标均已通过全量 `swiftc -typecheck`。诊断工具有一条字典类型推断警告，原始日志保留。优化编译、修改后截图/运行检查及安装包检查尚在继续，类型检查不代替这些步骤。
- 为避免诊断驱动变动混入性能结论，另保存了 `matched-driver-tools`。后加的次要页面截图场景没有改变 Home/Catalog 操作驱动或 Studio 编辑驱动，字节对照见 `numeric-driver-equivalence.json`。以该基线构建重新运行的 Home/Catalog/Studio 各三轮共 9/9 成功；早先的一次 Studio 重绘超时仍保留。


## 本轮最终结果与后续验收顺序

1. **已交付 0.2.3**：最终 stage11 的产品/诊断 typecheck 与优化编译通过，产品输入摘要一致；Universal 2 App/DMG 已在独立目录生成，旧包和用户已有改动保留，未提交或推送。
2. **实际运行证据**：最终源码功能/视觉 12/12、最终安装包资源 5/5 成功；Player/Practice 连续约 12 秒有真实时钟/谱面/数字音频，MusicXML 工坊有真实导入/录入/撤销/重做/保存内容核对与音频。28 张最终 PNG 已人工复查。详见 [运行证据](RUNTIME-DIAGNOSTICS.zh-CN.md)。
3. **性能对照**：两版本使用完全相同驱动，解锁后无并行编译，三轮共 18/18 成功。曲库主队列 P99 −33.6%；Studio 单次编辑原生 CPU −49.4%、约 12 秒编辑数 31→50。首页 CPU +6.0%、P99 +2.0%，没有测出整体改善，列为下一项性能调查；不将 CPU/定时器延迟称为 FPS。
4. **先补同状态视觉对照**：原网页服务恢复可用后，用相同数据、窗口和页面状态逐项对照导航、全部首页区块、三种曲库视图、个人谱区段、详情/练习、Studio 各面板及次级页面。当前只有源码/历史截图，不宣布像素级完成。
5. **再补全功能边界**：按完整清单覆盖各格式、原件/导出、Finder/拖放/保存与打印面板、备份恢复、并发/切工程/关闭/中断、所有音轨和声音所有权；长时性能与完整睡眠恢复需另行实机记录，现有短场景不能代替。
6. **发行前设备与签名**：在 Apple silicon 实机检查，测量动画帧时间/能耗，再完成 Developer ID、公证与安装体验。当前包 ad-hoc 签名，适用于本机安装复核。
