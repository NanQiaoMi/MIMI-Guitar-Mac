# 播放指针、阅谱布局、全屏与页面转场优化计划

日期：2026-10-25（Asia/Shanghai）  
基线：MIMI Guitar macOS 0.2.3（202610250756）  
状态：用户已于2026-10-25明确启动实施；正在按下列顺序修改源码，实际构建、播放与视觉验收结果另行记录。下列规划中的目标均不能直接视为已通过。

### 本轮修订：连续运动与进一步整理布局

用户追加要求：“要流畅的移动不是跳跃移动，界面布局还要再优化一下”。本次将**播放中的连续扫线**设为硬性验收条件，覆盖旧示意按拍量化位置的行为；标题/工具区进一步采用稳定主控、薄进度行和较轻的设置入口。更新的是计划与交互示意，实际 0.2.3 应用仍待实施。

### 最新追加：乐谱显示必须与原项目一模一样

用户明确要求：“乐谱显示的效果要和原项目一模一样”。**谱面完整复刻为发布门槛**，覆盖此前示意中的简化谱例。原项目的谱面渲染、字体、排版、谱页装饰和显示模式是唯一设计基线；此前手绘的四小节谱例仅记录过运动机制，不再作为乐谱外观、音符内容或排版的设计参考。布局优化的范围为标题、工具区和窗口交互，谱面自身依原项目复刻。

## 1. 目标与完成条件

针对用户截图中的四项问题，交付下一轮可安装版本：恢复随音乐移动的谱面指针，整理曲谱详情和播放器工具区，恢复真正可用的全屏阅谱，补齐与原网页一致的页面切换动画。沿用原网页的纸色、墨色、金色、字体、图标语义与功能内容，局部优化截图红框的编排。

完成条件：

1. 播放线在同一谱行内跟随真实音频时间连续扫过拍间位置，不能只在拍点跳动；小节高亮/当前拍准确，暂停、变速、循环、缩放和全屏后仍正确。
2. 默认工具区按用途分组，主要操作清晰，所有现有功能可找到且可操作；980 pt 宽度不重叠、不裁切、不靠缩小字体塞入。
3. 有常驻、可辨识的“全屏”入口；进出时保持当前曲谱、播放位置、音轨、速度、循环、缩放和同一 WKWebView。
4. 页面和面板从当前可见状态连续过渡至目标状态；遵循原站淡出、淡入和轻微归位，导航栏稳定，快速切换可平滑打断，返回位置正确。
5. 必要的播放位置保持连续；动效偏好与系统减少动态效果只收敛非必要的位移/缩放/装饰，不能把功能性指针改成逐拍跳动。
6. 类型检查、安装包检查、实际界面和运行证据分开记录；此前的声音/谱面就绪检查不替代指针、全屏和转场验收。
7. 同一谱文件、同一显示状态与有效谱面宽度下，原项目与Mac版的谱面内容、字形、尺寸、排版、颜色和分页一致；原有每种显示模式均有实谱对照证据。

## 3. 信息与布局设计

[查看更新后的工具区方案示意](../docs/evidence/native-player-ux-2026-10-25/proposed-layout-continuous-v2.png)。这是规划中的工具区结构截图，谱例为模拟内容、无音频，**不是已安装应用的修复结果**。其中的简化谱例已退出乐谱外观设计参考，最终谱面以原项目真实渲染结果为准。旧版示意截图另行保留，不能作为连续指针或谱面保真的验收证据。

### 3.1 视觉语言

- 继续使用当前原网页的纸张背景、墨色主文字、暖金辅助色与朱红进度/播放线。
- 详情标题与播放器对齐到同一内容边线；标题区域采用轻量分隔，播放器承担主要功能容器。
- 明确三层：曲谱身份与动作 → 播放/练习控制 → 谱面。主播放按钮保持最强视觉权重。
- 主控固定成组：左侧播放/重来，中部速度和练习辅助，右侧全屏；组间使用16–24 pt间距或细分隔，组内6–8 pt，不让所有按钮等权平铺。
- 进度条单独为薄行；次级设置使用安静的入口带和明确当前值摘要。减少重复的胶囊、边框和按钮背景，让谱面成为视觉中心。
- 布局展开时保留主播放按钮、进度与全屏的稳定位置。切换设置类别复用同一面板区；展开、收起和进入专注布局从当前呈现位置接续，不让整个谱面瞬间上下跳动。
- 控件文字以 12–13 pt 为目标，主要控件高 34–36 pt；图标、基线和间距统一。窗口变窄时调整分组与菜单，保持字号和操作目标。
- Menu 的可见触发器使用统一样式、状态和箭头，不在纸色按钮上混入不同尺寸的系统蓝色下拉框。保留系统菜单的键盘、焦点和辅助功能能力。
- 状态分别表达 hover、pressed、selected、disabled、loading、error、keyboard focus；禁用项有可理解原因。

### 3.2 标题区

宽窗口采用以下层级：

```text
返回  ·  吉他 / 专业 / 指弹谱 / G 调 / 66 BPM / 热度
斑马斑马  宋冬野                   收藏  加入待练  分享  更多
专业指弹谱，编配完整……                            
```

- 曲名和作者共用基线，标题和动作合理利用横向空间；长曲名允许两行。
- 返回与元信息保持轻量；收藏/待练状态直接可见。
- 分享直接可达；“更多”列出明确命名的下载原件、基于此谱改编及原有次级动作。菜单中的能力、确认、失败与取消路径保留。
- 说明默认 1–2 行，长内容展开；原文和完整曲谱元资料仍在页面中。
- 取消重复的大留白与多层卡片装裱。1280×800 逻辑窗口中，红框对应的标题+默认工具区目标不超过约240 pt；980×720时按重排目标不超过约300 pt。长标题/辅助功能字号可放宽，优先保证内容完整。

### 3.3 播放工具区

采用固定语义分组，避免所有控件按剩余空间自由散落：

```text
播放/暂停  重来  │ BPM 66  循环  节拍器              │ 全屏
2:56  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  3:38  第49小节·第2拍
纯六线谱 · 和弦名           演奏设置  显示设置  音轨  指板  导出
```

这是一份分组草图，实际可用宽度决定控件展开方式，不能机械照搬字符宽度。

| 原有能力 | 常驻入口/归属 | 完整保留的内容 |
| --- | --- | --- |
| 播放、暂停、重来 | 主工具行 | 实际引擎状态、加载中、失败、从头播放语义 |
| BPM | 主工具行 | 数字值与直接调整、原速、倍率/可达范围与警告 |
| 循环 | 主工具行 | A/B 设置、清除、区间、练习计划相关入口 |
| 节拍器、预备拍 | 节拍器常驻主工具行，预备拍在演奏设置；窄窗口可合并为练习辅助入口 | 两个独立状态与当前设置摘要 |
| 全屏 | 主工具行末端常驻 | 进入、退出、系统同步与无障碍标签 |
| 混合/纯线谱 | 当前视图摘要可点开显示设置 | 分段选择/命名菜单、各格式可用性与吉他/尤克里里文案 |
| 和弦名/指法图 | 同一显示设置内，与视图摘要同步 | 当前选中值清晰显示 |
| 变调夹、移调、恢复默认 | 演奏设置 | 原谱 capo、绝对 capo、移调数值和恢复范围 |
| 数字谱、缩放、分页/手稿 | 显示设置 | 原有数值、分页/图库与显示限制 |
| 音轨 | 设置入口带独立入口 | 可见/静音/独奏/音量/音色与恢复 |
| 实时指板 | 设置入口带 | 开关、当前状态、真实拍/音符同步 |
| 导出与打印 | 设置入口带末端 | 原件、完整 PDF、长图、打印、取消与错误 |
| 其它练习/恢复面板 | 原有命名面板入口 | 练习、回顾、片段、速度计划等，不用空白“更多”替代内容 |

所有面板在普通和全屏模式中使用相同数据源与能力，不复制状态。只在用户打开时显示对应内容；打开、关闭有明确归位。

### 3.4 滚动、重复播放条与空间

- 默认详情页中，播放器的主控区在阅谱过程中保持可达；谱面内部滚动和外层详情滚动有清晰边界，指针自动跟随只驱动谱面滚动容器。
- 当前主播放器与试听会话是同一首曲谱时，隐藏重复试听条，保留会话记录和焦点规则。
- 如果仍需展示另一首试听，明确标注“试听·已暂停/播放中”，采用预留空间的状态区，避免压在音符上。关闭、暂停、清空会话三个动作按真实语义区分。
- 继续使用现有单一音频 owner；转场和全屏不会创建第二个实际播放实例，也不由 ready/activeItem 推断正在发声。

### 3.5 乐谱显示的完整复刻契约

**实现来源**

原项目配置、组件、样式、渲染运行时与字体的11项文件摘要已保存为[谱面复刻基线](../docs/evidence/native-player-ux-2026-10-25/original-score-rendering-baseline.json)。该记录仅锁定实现来源，尚未进行实谱图像对照。

- 复用原项目同版本的AlphaTab及原有谱文件解析、转换与显示模式处理。优先提取共用配置和谱页样式，让网页与Mac引用同一份实现；本地资源URL和桥接单独适配。原生端的额外配置逐项列明原因，视觉配置不得另设一套默认值。
- 复用 `createScoreSettings()`、`installScoreLayoutFixes()`、`applyScoreDisplayMode()`、整小节休止处理和 `addLyricsTopSpacer()` 等既有处理链；确认各格式实际调用路径和处理顺序。音频/运行环境适配不得悄然改变谱面数据。
- 原项目内的现有显示规则原样保留，包括其元素显隐与密集和弦图处理；不依照源码注释里提及的其它参考网站另做一轮设计。

| 复刻范围 | 必须一致的内容 |
| --- | --- |
| 谱面内容 | 音符、品数、休止、节奏、连音/延音、重复与结尾、演奏记号、和弦、歌词及各音轨的可见信息 |

**排版与性能边界**

- 对照前等待原字体加载完成，校验字体资源摘要与实际使用的字体，消除系统回退字体造成的尺寸差异。100%缩放必须与原项目的100%含义相同；不能用原生默认scale=1代替原网页的基础缩放×用户缩放。
- 保留原项目的谱面有效宽度规则；普通窗口和全屏分别对照原网页相同状态。标题和工具区的高度优化不擅自改变乐谱横向边距、行内小节数或谱表间距。
- 性能改进采用资源预加载/缓存、稳定WK实例、消除重复排版与局部位置更新；原有音符、歌词、记号、音轨和显示模式全部保留，不压缩排版细节来换取流畅度。
- 正式谱面和后续设计预览使用原项目真实渲染结果。不得继续用手工简化SVG谱例、替代字体或固定假数据展示最终乐谱效果。

**一致性验收**

- 固定同一谱文件SHA、音轨及可见谱表、所有显示开关、变调夹/移调、有效谱面宽度、缩放和设备像素比，保存原网页与Mac的成对证据。先核对静止谱面，再核对同一真实tick的播放高亮。
- 同机同渲染后端下，叠加截图并检查SVG/DOM几何：字形、文字基线、音符与和弦位置、弦距、每行小节、换行与分页逐项一致。抗锯齿等后端差异单独登记来源，不扩大为可接受的排版或样式偏差。
- 使用真实《斑马斑马》及含歌词、密集和弦、多音轨、连音/重复/多段落的代表谱；覆盖IBE、GP、MusicXML与原有XHE/分页/手稿能力。每种格式和模式按原项目的实际能力核对，记录缺文件或不支持的场景。
- 本轮仅锁定要求并核对配置差异，尚未完成谱面保真修复或上述实谱对照。

## 4. P0：恢复实时播放位置

### 步骤

1. 使用截图的《斑马斑马》定位原文件，先核对元数据和时长，再 seek 到 2:56 附近及第49小节；找不到同一版本时如实记录，不用同名不同谱冒充复现。
2. 采集 `.at-cursors`、`.at-cursor-bar`、`.at-cursor-beat` 的存在、尺寸、computed style、viewport 交集和实际位置变化；同时记录真实 tick/播放状态。
3. 将原网页对应的运行时游标与高亮样式补入本地 player.css：朱红细拍线、低透明暖金小节底和当前音符高亮；明确叠层与 pointer-events，让拍线可见而不阻止点击。
4. 优先复用 AlphaTab 的 animated-beat cursor：其内置路径依据实际输出样本推进的时间/tick和tempo map，以线性 CSS transform 在拍间连续运动。原生 position 桥接约120 ms节流，只用于时钟/状态，不能用于驱动播放线，也不能额外用Swift定时器推进一条独立的线。
5. 当前拍由统一的真实位置映射提供；首拍从1显示，未知位置显示“—/定位中”，预备拍明确标注，避免“第0拍”。
6. 必要播放线在所有装饰偏好下都保持连续。Reduce Motion 可取消光晕、扫光、弹跳和大范围位移，但不能量化为逐拍/每120 ms更新，也不能对必要光标的transform施加全局transition:none。

### 连续运动的具体契约

- **时间与轨迹**：使用实际音频位置、相邻拍bounds与真实tempo map；同一谱行内在不等拍距、附点、三连音和速度变化下连续抵达正确拍点。同一行跨小节边界也必须连续，不能因每格单独留白而突然向前跳一段。播放位置使用线性时间关系，不能套带回弹/拖尾的缓动。
- **暂停/恢复**：暂停冻结最后真实位置，恢复从该点继续。当前本地引擎的暂停路径存在回到拍头的逻辑，需专门复现“回吸”并以最小适配处理，不直接修改所有曲谱位置数据。
- **变速**：以当前音频位置重定时间锚，校正剩余段时长；不先用旧速度走完、不重新从拍头播放动画。
- **换行**：在当前谱行连续扫至末端，在下一行真实起点交接，必要时用短透明度交接和连续跟随滚动；不能让线斜穿两行之间的空白。小节底色可以在边界短淡变，但不能取代连续拍线。
- **跟随滚动**：指针仍在当前阅读安全区时不滚动；即将换行或离开安全区时，以当前实际滚动位置为起点平滑跟随，并设阈值避免反复校正。不能每拍调用一次瞬时定位，也不能反复重启滚动动画；用户手动滚动后暂缓自动跟随，通过“回到当前拍”恢复。系统减少动态效果时收敛大范围滚动，必要拍线仍连续。
- **定位操作**：seek、重来、循环B→A属于明确定位，不把中间无关谱段假装全部播放。定位确认后立即以新时间/bounds为锚恢复连续运动；用户拖动时视图反馈连续跟手。
- **重排**：缩放、resize、切音轨和进出全屏后的bounds来自当前渲染结果；保留当前音频位置重新定锚，防止旧坐标拖尾。优先只改少量transform/opacity，不逐帧重排整个谱面或通知整个SwiftUI窗口。
- **时间轴滑块**：原生进度条也要连续跟随，不能直接把约120 ms一次的桥接值逐次画成台阶。在独立的进度视图内按同一音频时间样本与速度插值，暂停/seek/变速时重定锚；文字时钟与小节计数仅在语义值变化时更新。拖动期间用户输入优先，旧位置回包不能把滑块拉回。

### 验收

- 播放、暂停、恢复、重来、seek、A/B 跨小节循环与变速后，线、小节、音符和进度一致。
- 同一行稳定播放时有连续的拍间轨迹，而非8 Hz桥接刷新或逐拍台阶；暂停不退回拍头，恢复/变速不从旧起点重播。记录预期轨迹与实际位置的误差、停滞和掉帧，而非只看状态栏文字。
- 混合谱、纯线谱、数字显示、和弦模式、缩放最小/默认/最大、改变宽高、进入/退出全屏后均可见且不偏移。
- 手动翻看其它小节后遵循跟随策略；“回到当前拍”可恢复定位，不持续强行抢回用户滚动。
- 报告同时包含 DOM/样式/几何证据和真实播放时的画面；只验证音频非零或 SVG 数量不能算通过。

## 5. P0：全屏阅谱与稳定播放器

### 产品行为

- 工具行提供带图标和文字的“全屏”按钮；全屏时有持续可达的退出入口。
- “全屏阅谱”进入原生窗口全屏并展示专注布局：收起全站导航、标题说明和页脚，谱面使用剩余高度；顶部保留轻量传输、进度、设置与退出。
- 若窗口原本已处于系统全屏，只切换阅谱布局；退出时恢复进入前的窗口状态。菜单中可另提供窗口内“专注阅谱”，共用布局而不新增一套播放器。
- Esc 优先关闭当前弹层，然后退出全屏阅谱；系统绿灯/菜单退出也同步模式。窗口全屏沿用系统 Control+Command+F，谱面命令避免与已有快捷键冲突。
- 键盘焦点进入时交给退出/主播放控件，退出时归还原触发器；文件面板/弹层中的 Escape 不被全局退出处理抢走。

### 状态与架构

- 用共享展示状态协调 `standard/focused`、真实窗口全屏状态、进入前窗口模式与触发来源。
- 保持 **同一个 NativePlayerPane、NativePlayerModel、WKWebView 和音源实例** 挂载在稳定位置，只调布局约束、可见 chrome 和可用高度。
- ScoreDetailView/NativePlayerPane 节点继续留在原视图树位置，压缩或隐藏周围兄弟内容；不能用 focused/standard 两条条件分支替换整个详情页。
- 不用新的 Window/sheet 或两条 if 分支各创建一份播放器。全屏状态不参与 webViewIdentity；固定 520 pt 改为普通/专注布局各自的高度策略。
- 当前 pane 的 onDisappear 会暂停并离开练习，WK dismantle 会 dispose；展示切换必须避免误触发真正离开生命周期。
- 进入前记录外层阅读位置、WK 滚动/缩放、音轨与播放/练习快照；退出后在布局稳定时恢复。同一会话的数据仍由原模型持有，不进行重复导入或重新加载 SoundFont。

### 验收

- 播放中连续进出6次：WK 身份与加载计数不变，时钟连续，无重复声音/重载/跳回开头。
- 暂停、循环、变速、切音轨、开指板、导出/取消、原件缺失状态在全屏仍有真实入口。
- 专注布局不显示覆盖谱面的 AuditionStatusBar；另一首试听若仍有保留会话，状态和停止入口整合到设置/预留状态区，单音源焦点契约不变。
- 普通窗口→全屏阅谱→Esc，以及已全屏窗口→全屏阅谱→退出，两组分别恢复正确状态。
- 专注布局中谱面目标占可用内容高度至少80%，退出/暂停常驻；菜单和 HUD 不盖住当前演奏音符。

## 6. 页面转场与动效统一

### 6.1 统一策略

原网页当前 `motion.css` 的旧页、新页实际都使用page=280 ms；旧迁移文档中的exit=160 ms是通用菜单/面板token。此次保留原站节奏，并按用户最新要求将功能性连续运动与装饰偏好分开。页面和面板可被打断时，从当前实际呈现帧继续，不能瞬间重置动画起点。

| 场景 | 正常动态效果 | 轻柔/系统减少动态效果 | 用户显式选择静止 |
| --- | --- | --- | --- |
| 页面切换 | 旧页淡出、新页从当前可见状态淡入并从Y+6 pt归位；总计约280 ms，不硬重置起点 | 100–140 ms短透明度连续过渡，取消位移/缩放 | 页面直接到达终态 |
| 导航选中项 | 选中底块约200 ms从当前几何位置滑向目标，导航容器/标签宽度稳定 | ≤140 ms颜色/背景，取消空间移动 | 立即更新 |
| 控件反馈 | 120 ms 微反馈，保持聚焦可见 | ≤120 ms | 状态直接更新 |
| 面板 | 约260 ms、轻微位移/透明度；退出160 ms | ≤140 ms，纯透明度 | 立即展开/收起 |
| 全屏布局 | 窗口交给系统动画；内部 chrome 用短透明度变化配合，避免两套位移动画叠加 | 内部仅短淡变 | 内部直接完成；遵循系统窗口策略 |
| 必要播放位置 | 按真实音频时间连续移动 | 继续连续移动，取消装饰 | 继续连续移动，取消装饰 |

在 DesignSystem 中集中解析 `system/gentle/off + accessibilityReduceMotion`。Native shell 和 WK 的装饰动效按有效模式同步，避免各页面自行判断；同步不改变音源、真实进度和输入行为。

上表是对旧迁移契约的显式修订：本机系统减少动态效果开启时，收敛为短透明度过渡，取消非必要的空间运动；不再把它等同于所有功能反馈0 ms。用户主动选择“静止”时关闭装饰过渡，但真实播放线始终连续。全动态位移仍需在允许动态效果的配置下验收；本轮不修改用户系统设置。

### 6.2 导航、加载与快速切换

- 导航条、纸背景、隐藏 audition host 保持稳定；只对页面内容壳应用转场。沿用原站淡入/归位，不在路由中添加横滑、整页模糊或纸张翻转。
- 点击后先反馈选中/加载状态，异步读取继续；数据就绪或失败在当前页面内更新，不再重播整段路由动画，不用人为 delay 等数据。
- 同页筛选、分页和面板使用局部更新；不会触发整页退场。路由身份与播放器资源身份分别管理，避免全局 `.id(route)` 重建 WK/Studio。
- 连续点击时收敛到最后路由，沿用generation与取消规则；新动画从当前实际呈现位置/透明度接续，不能先跳到标准起始位置。过渡层至多保留当前页和一个轻量离场画面，不堆叠多个live editor。
- 面板展开/收起及全屏内部布局衔接要有完整起止帧，不使用直接display切换制造高度跳变。先取得目标布局，动画只作用于必要轻量层；谱面在最终尺寸重排一次，避免为了高度动画每帧重建AlphaTab排版。原生窗口全屏仍由系统处理。
- 离开播放器时按现有声音/练习策略立即结算；视觉淡出不延迟音频焦点释放。Studio 已接受编辑继续按既有队列排空，路由动画不取消草稿，也不等待最长20秒的销毁时限。
- 如使用离场快照，每次切页最多一次、转场结束释放；快照不接收输入或辅助功能焦点。旧实时视图不会在背后继续播放和动画。
- 历史状态补充外层滚动位置，按路由/筛选/排序/页码恢复；内容布局就绪后直接定位，避免返回时先跳顶再滚动。WK 内部滚动与外层位置分别保存。
- 动效偏好中途切静止、窗口隐藏或转场取消时，立即结算终态并移除遮罩，保持输入可用。

## 7. 性能目标与测量

以下为待验收目标，尚非已取得的结果：

- 主要操作在约100 ms内出现可见按下/加载/选中反馈；曲谱解析时间另行报告。
- 常规页面转场按280 ms token完成；不通过串行淡出再淡入把一次导航拉长为560 ms。
- 同机相同场景三轮比较，页面切换与全屏不引入持续定时器或 WK/音源重建；稳定空闲态没有新增装饰帧循环。
- 使用原生进程 CPU、50 ms 主队列心跳、实际界面/渲染事件分别记录；系统工具可用时再测帧时间、WebKit/GPU和能耗。工具不可用时标“未测”，不把心跳数据称为 FPS。
- 静态纸纹保留缓存，不逐帧重绘；导航不让90张卡片同时做模糊/阴影/尺寸动画；播放时钟不让整个窗口或标题区重复布局。
- 比较固定设备、窗口、谱面、编译参数与诊断驱动，避免并行编译；保留每轮数据和失败记录。首页原有性能问题仍需独立调查，不能由本轮新增转场宣告解决。
- 连续光标验收优先录制60 fps画面并采集有限逐帧位置/timestamp/真实tick/速度/谱行ID；60 fps是取证目标，不是尚未测得的产品性能结论。分开分析稳定行内运动、换行与显式seek，报告帧间停滞、非预期回退和与音频轨迹的误差；临时采样结束后清理，不带入产品常驻开销。
