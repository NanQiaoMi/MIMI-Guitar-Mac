# MIMI Guitar Mac 0.2.4 优化与验证结果

本轮代码和本机安装包已构建。验收分为“通过”“未执行”和历史失败，未把编译成功当作全部界面功能通过。用户指定的 GPT-6 Luna Max 子代理负责实现，主控负责计划、整合、构建与运行检查。

## 已完成的修改

- 谱面使用与原网页同版的 AlphaTab 1.8.4、排版设置、字体、显示模式、歌词预处理、和弦布局补丁和导出实现；初次显式显示所有轨道。
- 恢复朱红连续播放线、暖金小节高亮与自动跟谱，修正真实小节/拍号映射。变速和定位只接收音频 worker 确认的完整坐标，避免新 tick 配旧时间。
- 标题、作者和主要操作收紧为横向布局，窄窗口折行；工具按演奏、显示、音轨、指板、练习和导出分组，完整功能入口保留。
- 恢复全屏入口和菜单，进出时保持同一播放器、WKWebView、文档和音频上下文；退出恢复窗口与外层位置。
- 切页使用轻量淡入，正常动效加 6pt 归位。移除会造成数秒阻塞的同步整页截图；遵循系统减少动态效果和应用偏好。
- 原生进度条改为 NSSlider 输入与 Core Animation 绘制。文字由音频样本更新；滑块在样本之间连续移动。没有新增显示定时器或第二套播放时钟，拖动输入优先，定位和循环用 transportRevision 立即重锚。
- 首次排版等待 AlphaTab 初始化帧，隐藏期间等待可见并暂停加载超时，防止旧 SVG 累积或误报谱面损坏。

## 性能观测

| 同场景三轮中位数 | 0.2.3对照 | 0.2.4最终进度控件 |
| --- | ---: | ---: |
| 12秒播放的原生诊断进程CPU时间 | 0.780s | 0.606s |
| 50ms主队列心跳 P95 延迟 | 2.138ms | 2.081ms |
| 50ms主队列心跳 P99 延迟 | 5.526ms | 3.024ms |

最初60Hz整行SwiftUI刷新版本的CPU中位数为3.079s，已作为负例保留；改用系统合成动画后降至0.606s。最终三轮全部有实际音频和时间推进，测量期间未并行编译、压缩或运行其它MIMI诊断。

切页移除同步位图后，导航调用回到1ms内；这不是整个页面加载时间。曲库三轮P99由366.67降至267.91ms；首页P99由200.92降至189.13ms，但P95从32.82升至55.81ms，首页不能声称全面改善。

CPU只计原生诊断进程，不含WebKit、GPU与WindowServer；主队列心跳不是FPS。音频硬件采样率未锁定，两批音频时钟步长有差异，其他主机应用也未受控。因此这些数字是本机场景观测，不是跨设备、能耗或全部音频条件的统一结论。详见 `.build/runtime-audit-024/performance-024-progress-summary.json`。

## 保留的失败与修复依据

- GP5曾因漏过原项目混合谱休止预处理报 `highestNoteInHelper.beat`；已归入同版JSON转换链，后续实际播放通过。
- 字体曾在真正加载前缓存替代尺寸，导致名称模式每行0.84pt差异；保留原字体选择顺序，等待Cascadia后再创建引擎，最终38块一致。
- `clean-integrated-16` 隐藏态首次RAF未执行，切换后累积52/91/128个SVG；初始化屏障修复后的可见样本为正确13/13/12。
- `final-ux-13`曾在seek启动阶段出现一次636ms间隔和短暂x/y不同步；旧tick/time混合锚点已修正。最终记录把显式定位启动与稳定播放分开，不删除旧失败。
- 同步 `cacheDisplay` 转场曾造成7—12秒阻塞，已移除；原生进度条60Hz版本的CPU回归也已保留，未用只报延迟改善来掩盖CPU上升。
- AppKit缓存截图可能记录Core Animation的model终点，而非屏幕presentation位置；原生进度条用实际presentation读数单独核验。交付预览采用静止界面，避免把动画缓存截图当作播放位置证据。
