## 分工与实施阶段

1. **审查与复现**：工坊代理检查 ScorePlayer/PracticePanel 的触摸、A-B 与焦点；集合代理检查 PersonalPractice、片段和记录的恢复衔接；动效代理检查余下高频控件的偏好、隐藏和卸载生命周期。主代理核对分支、规则、服务、保护清单及旧验收边界。
2. **冻结实施范围**：依据真实路径给每个问题记录触发、当前后果、修复与验证；明确文件写所有权后才改代码。优先能被本机行为测试或真实浏览器证明的问题，避免宽泛重构。
3. **最小增量**：代理分别完成所属模块及必要行为测试；共享类型/方法先冻结契约。新异步命令需要取消、版本/代次、错误恢复及卸载边界，不在多个模块各自保存相互矛盾的状态。
4. **交叉复核**：由另一代理只读检查焦点、触摸默认行为、快速重复操作、减少动态与播放器连续性；修正之后冻结源码。
5. **验证与交付**：候选测试 → build → typecheck → 独立浏览器关键流程/多视口 → 文档与 diff 检查 → 提交 → `--no-ff` 合入 master → 实际 master 回归 → 更新本地预览与原树保护复核。

## 审查后实施清单与实际结果

### 已确认：和弦预览与工坊切换状态

- 首页 Hero/典藏和弦按钮仅响应 mouseenter/mouseleave，键盘与触摸缺少可靠打开方式；曲库虽有 focus，但触摸点击语义仍不完整。三处固定向上展开，靠近视口顶端或两边会被裁切。
- 动效代理独占三处调用文件 `home/HeroShowcase.svelte`、`home/MasterpieceStage.svelte`、`TabCardGrid.svelte`，以及所需共享和弦预览 helper/component 与专属测试。保留原弦位 SVG 和视觉基调；统一 focus、hover、点击固定/关闭、Escape、点外与失效清理。focus→click 不可导致触摸第一次点击立即关闭；弹层是只读信息，不移动焦点，不拦截卡片导航。
- 按实际弹层尺寸和锚点空间选择上/下方并约束坐标，滚动或尺寸变化时更新或关闭；不得出现离开锚点仍滞留的弹层。动画用既有共享 surface；轻柔/静止模式保持功能位置，限制可见区域。
- 同代理独占 `studio/StudioHeader.svelte` 的三个切换按钮，只补明确名称及 `aria-pressed`；不改播放业务动作。浏览器检查前后真实状态和名称。
- 定向行为测试验证边缘坐标、交互切换和取消/卸载；实际浏览器以首页/曲库键盘和点击、滚动和窄屏复核。触摸模拟与真实设备分别记录。

### 已观察的练习布局问题

390×844 基线页面没有横溢出，但个人练习面板高约1045px、谱面 top 约1779px。练习控制与谱面距离太长；待对应代理确认最小折叠/紧凑方案及焦点、挂载和草稿边界后实施，不以隐藏播放器或卸载业务状态解决。

### 已确认：拖动取消、紧凑练习与变调夹焦点

- 主进度条只有 down/input/up/keyup，触摸转为纵向滚动后 pointercancel 可让 `dragging` 常驻，预览位置遮住真实引擎位置并使练习控件持续禁用。悬浮进度条也有同类未取消预览。工坊代理独占 `player/ScorePlayer.svelte`、`player/FloatingPlayerHUD.svelte`、`practice/PracticePanel.svelte` 及专属进度预览 helper/test，统一完成正常提交和取消收尾。
- 取消不得发起 seek 或保存预览 tick；恢复最新引擎确认的位置与拍信息，清除预览状态。pointerup 已提交后的 lostpointercapture 不得取消有效回执；加载新曲、卸载/隐藏时不得带旧拖动状态。键盘改值仍能正常提交；不改现有真实 tick/反复段映射和 receipt 协议。
- 练习详细设置改为可显式展开的紧凑区域，常用加入/开始/暂停/结束/继续上次、当前位置、备注和已确认时长留在外层。优先使用保留子树的原生 details；窄屏默认紧凑、桌面保持可发现。折叠不清草稿/片段/选段或重挂播放器，隐藏内容不可聚焦；模式切换不自动抢焦点或自动播放。说明文案简化为操作指引，内部 tick 协议保留在开发文档。
- 变调夹选项达到44px，并补清楚的弹层/列表语义；选择和Escape关闭后焦点回触发器，点外不抢回外部目标焦点；expanded 与实际可见一致。混音/渲染/播放连续性保持已有契约。
- 定向测试覆盖取消/重复终止/提交后丢失捕获/键盘提交/数据切换，实际浏览器检查焦点、尺寸、折叠草稿与同一谱面节点。无法通过现有浏览器入口生成真实触摸取消时明确区分单测与真机未执行。
- 390×844 实测主播放进度 input 高度只有4px；须扩大实际命中框到44px并保留细视觉轨道。IAB 不支持 `Input.dispatchTouchEvent`，未生成触摸取消事件，临时触摸模拟已清除；此项必须以控制器行为测试和后续真机证据区分，不用脚本注入事件冒充触摸。

### 已确认：恢复入口、队列触控与备注草稿保护

- 外部归档使 `selectedId` 清空但保留 URL 请求；同曲恢复后非首次数据订阅直接返回，原页卡在旧错误。集合代理独占 `PersonalPractice.svelte`，只在 URL 明确请求的曲谱重新成为 active 时恢复选择，不因任意资料更新自动选别的曲目。
- 同代理独占 `practice/PracticeReview.svelte`、`practiceSummary.ts` 与专属测试，最近记录带上 scoreId 和当前待练状态：活跃且存在的谱给普通 `/practice?score=` 链接；归档、移出或缺失的谱给正确恢复/管理提示，不能把所有历史项当作可续练。不得更改原记录时长、版本或 schema。
- 同代理独占 `PersonalLibrary.svelte` 的队列操作尺寸修正；选曲 select、管理入口和队列控件不小于44px，窄屏允许换行。
- 备注失焦写入若失败，切曲会卸载原组件并丢掉草稿/重试。采用一个小型的异步离开护栏，集合代理新增 `src/lib/practice/practiceLeaveGuard.ts` 的导出类型 `PracticeLeaveGuard = () => Promise<boolean>`、`RegisterPracticeLeaveGuard = (guard: PracticeLeaveGuard) => () => void` 及所属协调器行为测试。协调器在组件清理/替换后不能接受旧结果；快速选择只有最新请求可切换。
- 工坊代理在 ScorePlayer 接收可选 `onRegisterPracticeLeaveGuard?: RegisterPracticeLeaveGuard` 并原样传给 PracticePanel 的同名可选 prop。Panel 注册只负责备注的护栏：等待既有保存，再保存最新 dirty 文本；失败返回 false 留在当前曲，输入/重试保留；未开始会话的遗留草稿给清楚提示，不静默丢弃。显示保存中及显式保存/取消编辑，待保存期间禁止取消造成假撤回。普通浏览器离页使用仅 dirty/saving 时的 beforeunload 提醒，不引入全局链接劫持或等待动画。
- 选曲组件必须在护栏通过前保持当前播放器和 select 的已确认值。订阅/历史导致的恢复需继续遵守最新代次及源身份核验；此护栏不改变已有会话 writer、音频引擎或数据协议。跨标签强制移除和版本变化的异常路径单独复核，不把旧备注写到新曲。
- 定向测试模拟延迟保存、拒绝、组件替换和快速重选；浏览器验证正常保存后切曲、回顾入口、双标签归档/恢复及44px布局。无法观察原生确认窗时不宣称该弹窗已验收。
- 首页 `StudyNotesFeed.svelte` 的最近三条同样按存在/待练状态选择练习或管理入口，并复用现有 latest-read 协调器防止迟到读取覆盖新状态；不为首页重新汇总全量历史时长。此文件追加由集合代理独占。
- 交叉复核发现备注保存与结束的最终写入没有 note 基准校验。主代理独占 `practiceSessionWriter.ts` 与对应测试，仅新增事务内 `expectedNote` 比较与共享冲突类型，不改数据 schema、计时或写队列协议。工坊代理在首次编辑时捕获 note baseline，普通保存和结束均使用该基准；外部修改则保留草稿、刷新已保存值供取消编辑使用，不给无效的盲重试。此项是保存前读取无法消除的真实竞争窗口，必须在最终 mutation 中校验。

全部实施文件已有单一写所有者；主代理负责文档、集成审查、浏览器、服务及Git。最终记录变更文件、候选和主分支命令结果、提交号、环境与设备限制。

## 集成复核补充

- 进度预览在拖动期间持续记录引擎确认的位置；取消时恢复最新值，提交时与最新值比较。这样既覆盖拖回起点时引擎已前进，也覆盖 A-B 回绕、曲末和提交后丢失捕获。
- 折叠区在全部尺寸默认关闭，保留子树、草稿和播放器；使用原生 details/summary 避免首次 hydration 改变展开状态。变调夹选择与 Escape 关闭回到触发器，点外关闭保留外部目标的正常焦点。
- 切谱护栏共享同一次保存等待，只有最新明确选择可应用。保存期间的订阅读取不得抢走选曲；原曲重选会使旧请求失效。原生 select 在护栏通过前显示已确认的曲目。
- 和弦预览的 hover、focus、点击固定独立处理；曲库切换视图、筛选后锚点失效或滚出视口都会关闭。弹层按实际尺寸翻转和夹取，箭头跟随锚点中心；使用既有动效偏好和 surface 过渡。
- 工坊三个开关经 AlphaTab 1.8.4 本地代码与类型声明复核：ScoreStudioApp 将状态传到 ScoreCanvas，后者响应式写入 metronomeVolume、countInVolume、isLooping；没有发现其他覆盖赋值。此前“native 未接通”的怀疑已撤回，不添加重复播放桥接。
- 第一轮集成检查发现三处和弦位置类型名称不一致，以及离开护栏空会话参数不符合类型约束，均作为候选问题修复后重新检查；只有最终重新执行的检查计作交付通过。
- 浏览器追加复核：320px 下流动根字号会让 `min-h-11/min-w-11` 缩小到约40px，新增触摸控件改用明确44px，首页和弦组允许换行。现有指法库没有 Eb 等部分名称，原来无反馈；改为明确的未收录说明，不猜测或伪造新指法。首次在 SSR 按钮尚未确认 hydration 时的键盘尝试不计作通过，客户端就绪后重新验收。
- 完整动效模式额外暴露 Hero 磨砂容器的 fixed containing block：传入视口坐标后，弹层实际 top=-90.2px且被 overflow-hidden 裁切。将固定弹层移出自身磨砂/reveal 根容器，保留原磨砂和纸张样式；三种动效模式须重新测量实际视口边界，不能只依赖纯坐标测试或轻柔模式截图。
