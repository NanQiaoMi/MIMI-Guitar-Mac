# 练习与播放契约

本文记录 `ScorePlayer`、`PracticePanel` 与音频焦点辅助模块实现的播放和练习行为。续练断点保存在本机；恢复时不会自动播放。

## A/B 循环与渐进提速

- A/B 区间使用展开后的谱面 tick，区间为左闭右开 `[A, B)`。只有从 A 不间断播放到匹配的 AlphaTab 循环结束事件，且页面可见、播放仍在进行、本标签持有音频焦点时，才计为完整一圈。
- B 包含所选拍的实际拍末；进度停在曲末 `tick === endTick` 时允许 B 恰好取 endTick，禁止再加一。超过曲末、未知或矛盾的拍末须报错并保留旧区间。倒选使用设置 A 时捕获的 A 拍末归一化，不能丢掉原来 A 所在拍。
- 跳到区间中间会清除未完成进度。AlphaTab 1.8.4 有时会把 A 点 seek 回报晚一个 tick，因此 seek 到距 A 一 tick 以内可以开始计圈。暂停、失去焦点、标签页隐藏、区间变化或 seek 都会清除未完成的一圈。
- 提速计划绑定具体谱面 revision、A/B 区间和 A 点原始速度。完成一整圈后才推进，实际 AlphaTab 倍率为 `target BPM / native A BPM`；达到目标后停止推进。
- A 点原生速度从 AlphaTab 当前 MIDI tick cache 的展开 masterBars/tempoChanges 查询，包括冷启动、小节内变速和反复经过；缺失或越界时保持未知。反向选 B 导致区间起点改变时，必须按最终 A 点重新查询，不能沿用原光标的速度事件。
- AlphaTab 倍率必须是有限数，且在 `[0.125, 8]` 内。目标控件和保存字段 `speed` 的范围是 `[20, 300]` BPM。`playbackRatio` 独立保存引擎实际倍率，因此原始速度高于 300 BPM 时不会被改写为目标速度。没有设置目标时，400 BPM 曲谱保持 `1×`，并显示实际 400 BPM；目标控件上限仍为 300，并解释两者区别。显式目标只能选择 `[20, 300]` 与倍率可达速度范围的交集。

## 续练、暂停与结束

- 续练快照保存 AlphaTab API 当前 tick 和时间、实际播放倍率、变调夹/移调、循环区间、可见音轨、音轨静音/独奏/音量/音色，以及谱面显示设置。只有谱面 revision 相同且音轨索引在当前曲谱范围内时，才恢复音轨和显示设置。
- 恢复顺序为：先应用显示和音轨选择，再按已保存的变调夹/移调和乐器重建谱面与 MIDI，然后应用混音设置，最后恢复倍率、循环和位置。恢复后保持暂停。新断点精确恢复 `playbackRatio`；缺少该字段的旧断点使用兼容计算 `speed / source tempo`，并显示“旧断点未含实际倍率，位置已恢复，请确认速度”，除非匹配的提速计划能明确给出倍率。
- 新加载未显式指定变调夹时保留各轨原谱 capo，界面可返回“使用原谱”；显式数值选择才统一覆盖。断点通过可选 `useSourceCapo` 区分这两种模式，旧记录缺失时保持原数值覆盖行为。音轨原始零音量必须仍是 0，不能被缺省值改为满音量。
- 暂停和结束时，先捕获引擎位置，再改变播放器状态。续练写入会串行执行，避免较早的检查点覆盖暂停或结束边界。结束会话先保存该边界，再调用显式 stop 重置可见位置；整曲自然播放结束则保留终点断点。用户下一次明确点击播放时才从 tick 0 开始，并将新位置记为用户操作。
- `PracticePanel` 的会话更新统一设置 `updatedAt = max(Date.now(), latest.updatedAt + 1, proposed.updatedAt)`。系统时钟回拨或恢复的未来时间戳不会让新备注或结束状态输给仓库按时间戳合并的旧记录。若更新带有 `endedAt`，会将其限制为不早于 `startedAt`。该处理不会增加练习切片时长。
- 跨标签资料刷新会按数据库中的会话 ID 和状态对齐本地状态，并丢弃过期刷新结果；已结束或已移除的会话会停止本标签播放计时、清除该会话尚未保存的计时切片，并从面板清除。会话更新、收尾切片和排队写入都绑定曲谱 revision 与会话 ID；数据库事务内拒绝修改已完成记录，所以较晚到达的旧切片不能写入新会话，再次练习会创建新会话。
- 备注只在本地内容没有未保存编辑时才随跨标签刷新更新。若另一标签页结束会话，未保存的备注草稿仍显示在面板中，并在下次开始练习后可继续保存；保存时会再次核对原会话身份。
- 断点自动保存间隔使用 `performance.now()` 单调计时，不依赖系统墙钟；墙钟回拨不会延长 5 秒保存间隔。第一次有效断点立即可写，存储失败会清空间隔基准以允许重试。
- 只有页面可见、播放进行中且本标签持有音频焦点时才累计练习时长。计时按切片写入，暂停或结束时关闭最后一片；`durationMs` 来自 `performance.now()` 测得的经过时间，不使用墙上时钟间隔。
- 参数/播放器操作提示与真实保存故障分别呈现；只有保留了具体待写操作的故障才提供“重试保存”。普通自动保存成功不能清掉 A-B 参数错误。旧谱版本断点保留并注明不可直接恢复，避免错套到新版。

## 命名片段与写入控制器

`PracticeFragmentLibrary` 负责表单、列表、就地修改和删除确认；`PracticePanel` 负责校验、播放器协调与 UI 草稿；无 Svelte 依赖的 `practiceSessionWriter.ts` 拥有串行会话写入、稳定 pending slice、单调计时边界与 checkpoint/close/finish 顺序。领域函数保留 completed 终态及切片幂等规则，仓库保留 IndexedDB 原子事务和广播。

片段应用前校验当前谱面 ID、实际内容 SHA、更新时间、区间和倍率；旧版本片段保留但要求重新选区。应用先暂停并持久化本次切片和断点，失败则保持暂停并阻止后续设置；成功后设置区间、定位 A、填入参数并应用起始倍率。它不创建会话、不播放、不启用提速计划；用户明确开始练习及提速后，从起始 BPM 和零圈开始。片段备注不覆盖 session 备注。切谱期间的迟到回调不能更新新谱表单或播放器。

pending slice 绑定固定单调起止边界，成功重试只推进到实际保存的边界；暂停收尾失败后的重试不计等待存储恢复的时间。结束等待切片、断点与 completed 提交成功后才调用 stop；失败保留草稿和可重试切片。控制器测试与本轮浏览器验证分别记录在[迭代记录](architecture-and-fragments-plan.md)。

## 音频焦点与控件

- 浏览器锁 `mimi-audio-focus-v1` 管理当前可发声的播放器。`BroadcastChannel` 协调跨标签暂停和释放焦点。失去焦点会暂停播放并清除未完成的一圈。
- 播放与练习控件在可行处使用 44 px 触控目标；进度和速度输入有可访问名称，切换控件带有按下/展开状态，原生范围输入和按钮可用键盘操作。窄视口会隐藏悬浮播放器的回到顶部按钮，避免控件超出屏幕。

## 验证证据与边界

- fresh build 全套自动化测试使用临时数据库：234 项通过、0 项跳过、0 项失败；`npm run build` 与 `npm run typecheck` 均退出码 0。静态诊断含 60 条 Svelte 警告和 41 条 Astro 提示。
- 同源双标签浏览器实测：A 的自然播放结束后保存 21 秒；B 加载同一未结束会话时显示继续/结束操作。A 结束会话后，两页立即恢复“开始练习”；B 随后开始会创建新会话。两页分别结束后，v1 导出 revision 103 含 4 条已完成会话；A、B 会话 ID 不同，分别有 5 片/21,320 ms 与 4 片/21,080 ms。Node 导出载荷验证、4 个资源 SHA-256 校验和严格数据结构校验均通过。
- 窄屏 HUD 实测：320×740 视口 clientWidth/scrollWidth 均为 305 px，三个 HUD 按钮高度均为 44 px 且最右端小于 299 px；390×844 视口两者均为 375 px，按钮高度为 44 px。768、1024 和 1366 px 视口无全页横向溢出，截图证据为 07–11。此前 fresh4330 上的自然末尾断点、400 BPM 与 A/B 65 BPM 浏览器证据记录在项目实现文档中。
- 自动化测试和浏览器交互结果不能证明声音可闻或真机行为。iOS、Android、Safari 真机验证，以及 2 小时播放、30 分钟移动设备播放和 1 GiB 数据量测试尚未执行。
