## 3. 首期功能与故障验收

## 4. 固定测试资源矩阵

新增 fixture 以自制/可用测试谱为主，不依赖外部站点稳定性。至少包含：

- 短单轨吉他；长指弹谱；带歌词/和弦密集谱；六线与五线联动；多轨混音；尤克里里和贝斯。
- 同一谱面反复多次、第一/第二房子、跨区变速、混合拍号、全休止/末尾长音/无声轨。
- 可正常导入的各声明格式、损坏/空/超大/无可编辑弦轨文件、未来 schema 和损坏草稿。
- 小/大备份包、同 ID 不同版本、重复会话、缺附件、错误 hash、超限压缩与非法路径。
- 每个文件带来源、用途、hash 和预期语义摘要；测试失败不自动替换 fixture。

## 6. 每个任务的交付与回滚

提交前：变更路径清楚；边界与数据兼容写明；目标测试/类型/构建完成；影响的浏览器场景有证据；失败和未执行项列明。禁止无谓全仓格式化、顺带重写未涉及模块。

合并前：代码任务不存在新增失败或涉及失败文件的未解决诊断；文档分支可携带明确已知基线，但不能宣称全绿。完成提交后 `git merge --no-ff`；合并后检查主分支相关回归。旧 dirty 工作区不被清理。

回滚：代码用 revert；本地数据用可回退代次/导出包；服务端资产与数据库有协调恢复点。不能通过删除未合并分支或 reset 共享历史“完成”回滚。
