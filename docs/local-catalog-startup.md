# 已有本机曲库的启动与诊断

使用 Node.js 24。曲库数据库、谱文件和音源分别需要就绪；网页能打开不代表真实曲库已连接。个人导入、待练和练习记录保存在当前浏览器，不依赖服务端数据库写入。

## 日常启动

本入口用于已经存在的 `mimi-guitar-pg` PostgreSQL 容器。先在 Docker Desktop 中确认引擎及这个已有容器正在运行，再在已准备媒体的项目目录执行：

```powershell
npm ci
npm run prisma:generate
npm run build
npm run start:local -- --check
```

前三条在首次准备工作树或更新依赖、代码后执行；日常重启只需检查和启动。`--check` 只读检查数据库，不启动网站。通过后，可以在同一终端启动：

```powershell
$env:HOST = '127.0.0.1'
$env:PORT = '4336'
npm run start:local
```

应先停止占用目标端口的自己的网站实例。不要为了切换服务清空浏览器数据；个人资料与站点地址绑定，换端口需要通过备份迁移。

启动入口检查既有容器身份、PostgreSQL 镜像、持久化挂载、已发布端口、五个 Prisma 模型的52个标量列、迁移状态和非空曲库。列检查包含类型与可空性，不读取账号内容。应用客户端使用 `127.0.0.1`；这不会更改已有容器对外发布端口的范围。凭据从既有容器配置传入网站子进程，不写入项目文件，也不输出连接串。

若当前终端已经设置 `DATABASE_URL`，它必须指向同一个已确认的本机数据库；缺失的连接/连接池超时只在派生连接中补为3秒，已有1–5秒的安全值和 `schema=public` 保留。重复、未知或无界的参数会被拒绝。目标不一致时检查会失败。先确认该变量属于旧测试会话后，可以仅清除当前终端的变量，再重试：

```powershell
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
npm run start:local -- --check
```

## 如何判断恢复结果

| 检查 | 能证明的状态 | 仍需核验 |
| --- | --- | --- |
| `npm run start:local -- --check` 成功 | 已有本机容器与数据库符合启动要求，曲库非空 | 网站尚未启动；资源尚未检查 |
| `/api/health` 返回 200 | 网站进程存活 | 数据库、曲库与媒体仍可能不可用 |
| `/api/readiness` 返回 200 | 数据库、迁移、曲库资源抽样及基础音源通过 | 每类最多抽查20条引用，不能证明全库资源完整 |
| `/api/search?limit=1` 的 `source` 为 `catalog` | 本次搜索实际读取数据库 | 仍需打开详情并取回对应原谱 |
| 原谱请求成功并实际渲染 | 本次选择的曲谱可取回、解码与显示 | 不代表全库、所有设备或声音听感通过 |

数据库不可达时，readiness 中迁移和曲谱资源的计数没有经过查询；不要将占位的零或待迁移数当作数据库为空、丢失迁移的证据。

## 故障处理

| 现象 | 下一步 |
| --- | --- |
| Docker 命令超时、引擎不可达 | 先恢复 Docker Desktop 引擎；窗口进程存在或提示 already running 都不能证明引擎已就绪 |
| 既有容器未运行 | 在 Docker Desktop 中启动已有的 `mimi-guitar-pg` 后重试 |
| 容器、镜像、挂载或端口身份不符 | 核对既有项目部署；不要通过新建空数据库消除提示 |
| 已设置的连接与本机目标冲突 | 确认终端变量来源，再按上面的命令清除旧测试变量 |
| 数据库连接失败 | 检查引擎、既有容器与端口；不要把连接失败当作 schema 缺失 |
| 迁移或表结构不匹配 | 先确认实际库及备份，另行制定保留数据的升级步骤 |
| 曲库为空 | 确认挂载的是原数据库；本入口不导入备份或填充演示数据 |
| 数据库通过但 readiness 的媒体检查失败 | 根据实际缺失引用恢复媒体并重新构建；使用 README 中的资源准备与核验命令 |

本入口不创建、启停或重建数据库容器，不修改表结构，不运行迁移、seed 或备份恢复。数据库集成测试使用独立的 `mimi_platform_test`，不能对真实曲库运行会写入夹具的测试。

## 个人练习与降级启动

`npm start` 仍直接启动已构建的网站，沿用调用环境的连接配置，允许数据库不可用时的个人导入与练习流程。页面会如实显示演示降级；该模式不能作为真实曲库恢复证据。

本轮实际故障与验证结果记录在 [恢复计划](catalog-runtime-recovery-plan.md) 和 [验收记录](evidence/catalog-runtime-2026-10-20/README.md) 中。
